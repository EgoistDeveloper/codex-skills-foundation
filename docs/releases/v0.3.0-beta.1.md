# v0.3.0-beta.1 release notes

`v0.3.0-beta.1` is the first public beta release centered on `engineering-foundation-core`.

## Package versions

- `engineering-foundation-core`: `0.3.0-beta.1`
- `engineering-foundation-laravel`: `0.2.1`
- `engineering-foundation-design`: `0.2.1`
- `engineering-foundation-cloud`: `0.2.1`
- `engineering-foundation-authoring`: `0.2.1`

Only Core is version-bumped because it is the package that received the expanded authenticated live-behavior campaign. The optional packages remain available at their previously validated versions rather than receiving decorative version inflation, a surprisingly common ceremony in software releases.

## Core behavior included in the beta

- task contracts with stable acceptance IDs;
- bounded planning and milestones;
- bounded orchestration with one writer per file and delegation depth one;
- surgical implementation guidance;
- systematic debugging with reproduction before edits;
- source-grounded research;
- material diff review;
- evidence-gated completion;
- compact handoff.

## Authenticated Codex CLI evidence

The beta is backed by recorded Codex CLI campaigns for Core `0.2.2`, whose skill content is promoted into the beta candidate:

- explicit debugging: `3/3` repeated candidate passes;
- tiny edit non-activation: `3/3` repeated candidate passes with zero subagents;
- positive bounded delegation: one pass with two direct children, zero nested children, no writes, and complete parent integration;
- failed-evidence refusal: one pass with verifier exit code `2`, a structured `BLOCKED` packet, and no false `COMPLETE` claim.

All recorded campaigns restored the original Codex marketplace, plugin, and configuration state. See [`../qualification.md`](../qualification.md) and [`../live-evidence/`](../live-evidence/).

## Distribution guarantees

- strict repository validation;
- Linux and Windows bootstrap;
- deterministic ZIP packages;
- byte-identical Linux/Windows package output;
- Claude marketplace/plugin validation;
- Codex marketplace and package-install smoke;
- no bundled MCP server, hooks, telemetry, credential bridge, recursive delegation, or global installer.

## Final beta lifecycle gate

Before the tag is published, maintainers run:

```text
python scripts/run_public_beta_lifecycle.py
```

The zero-model harness verifies a disposable Git-marketplace lifecycle from Core `0.2.2` to `0.3.0-beta.1`, all-package install and namespaced discovery, complete package removal, marketplace removal, and clean isolated configuration.

## Known limits

- live behavior is qualified only on the recorded Codex CLI surface;
- positive delegation and failed-evidence refusal currently have one repetition each;
- the beta reduces operational hallucination risks but does not eliminate factual hallucinations;
- optional packages have static/provider validation but not equivalent live-behavior coverage;
- token and duration measurements show that stronger verification can cost substantially more than a baseline.

The release is therefore a public beta, not a universal live-model qualification claim.
