# Skill and plugin release checklist

- Capability and non-goals are narrow.
- Description has positive and negative trigger boundaries.
- `SKILL.md` stays compact; details use one-level references/assets.
- Provider manifests and skill metadata validate.
- No secret, privileged hook, MCP, network, or global mutation was added without an explicit threat model.
- Provenance and license decisions are recorded.
- Positive, explicit, negative, skip, failure, and overlap eval cases exist.
- Deterministic repository and package checks pass.
- Supported provider installs validate.
- Live behavior qualification is recorded separately from static checks.
